# Bug Triage Agent — v0.3 (Dynamic)

A Langflow agent that takes a Jira issue key, fetches the real bug report from Jira, and returns a structured triage verdict (severity, priority, and QA recommendations) generated by a DeepSeek LLM.

> **Flow ID:** `069c4b88-7853-416d-87f9-d6f7df88acfe`
> **Flow file:** `002_Agent_Dynamic_Bug Triage v0.3.json`

## Overview

This is the **dynamic** version of the Bug Triage agent. Unlike the earlier versions (v0.1 / v0.2), which had the bug report hard-coded, v0.3 accepts a **Jira issue key at runtime**, looks up the live issue from Jira, and triages the actual bug it finds.

Given an issue key like `KAN-1`, the agent:

1. Fetches the issue from Jira's REST API.
2. Parses the response into readable text.
3. Feeds it to DeepSeek with a "senior QA" triage prompt.
4. Returns a structured report: **severity**, **priority**, and the **QA's comments / recommendations**.

## How It's Built — Langflow Components

The flow wires together **7 components**:

| # | Component | Role |
|---|---|---|
| 1 | Chat Input | Receives the Jira issue key from the user (e.g. `KAN-1`) |
| 2 | Prompt Template (`issue_key`) | Builds the Jira API URL: `.../rest/api/3/issue/{issue_key}` |
| 3 | API Request | `GET`s the issue from the Jira REST API (Basic auth) |
| 4 | Parser | Converts the JSON API response into plain text |
| 5 | Prompt Template (`result`) | Wraps the parsed bug into the triage prompt (`{result}`) |
| 6 | DeepSeek (`deepseek-chat`) | Generates the triage analysis |
| 7 | Chat Output | Returns the final report to the user |

## Architecture

```
Chat Input (issue key)
   │  message → issue_key
   ▼
Prompt Template   ── builds Jira URL ──►   https://…/rest/api/3/issue/{issue_key}
   │  prompt → url_input
   ▼
API Request (GET)  ── fetches the issue ──►  Jira Cloud
   │  data → input_data
   ▼
Parser  ── JSON → text ──►  parsed bug details
   │  parsed_text → result
   ▼
Prompt Template  ── "You are a senior QA… analyze a bug report {result}…"
   │  prompt → input_value
   ▼
DeepSeek (deepseek-chat)
   │  text_output → input_value
   ▼
Chat Output  ──►  Structured triage report
```

## Approach

The agent follows a **fetch → parse → prompt → generate** pattern:

1. **Fetch** — the API Request component does a `GET` to Jira with the issue key injected into the URL, authenticated with Basic auth (email + API token).
2. **Parse** — the raw JSON response (a Jira issue object) is flattened into readable text by the Parser component.
3. **Prompt** — the system message sets the persona: *"You are a senior QA who helps the user to do bug triaging…"*, and the parsed bug is injected as the `{result}` variable.
4. **Generate** — DeepSeek returns the structured output: **severity**, **priority**, and **QA comments** (root-cause hypotheses, missing information, and test-coverage suggestions).

## UI

A lightweight React frontend (`langflow-chat-ui/`) runs the agent:

- A text box for the **issue key** and a **Run** button.
- Sends `POST /api/v1/run/{flow_id}` with `input_value` set to the issue key.
- Renders the markdown report (tables and headings) in a clean light theme.

## Setup & Usage

1. Import `002_Agent_Dynamic_Bug Triage v0.3.json` into Langflow.
2. Configure the **DeepSeek API Key** (via a Global Variable or the component field).
3. Set the **Jira credentials** used by the API Request (see Security Note below).
4. Run the flow — either in the Langflow Playground or through the `langflow-chat-ui` frontend.

## Security Note

The API Request currently stores the Jira **Basic auth header** (email + API token) directly in the flow. This should be moved to a Langflow **Global Variable / Credential** so it isn't embedded in the exported flow JSON. Rotate the Jira API token if this flow has been shared or committed to a repository.
